# Wallpaper — спецификация

Менеджер обоев для Windows 11: статика, слайд-шоу, независимые мониторы, видео-обои, трей, глобальные горячие клавиши.

> **Сначала честно:** [Lively Wallpaper](https://github.com/rocksdanister/lively) (C#/WPF, MIT, бесплатно) закрывает ~90% этого списка уже сегодня. Если цель — «чтобы работало», ставь его. Дальше — если цель «написать своё».

---

## 1. Цели и не-цели

**Цели**
- Разные обои на каждом мониторе, независимо.
- Плейлисты изображений (папки + отдельные файлы), слайд-шоу с интервалом и перемешиванием.
- Видео-обои (mp4/webm/mkv), бесшовный цикл, аппаратное декодирование.
- Иконка в трее + меню, окно настроек.
- Глобальные горячие клавиши: следующая/предыдущая, пауза, переключение плейлиста.
- Автозапуск, минимальный простой (idle CPU < 1%).
- Автопауза видео в играх / на батарее / на локскрине.

**Не-цели (сознательно)**
- Мастерская контента / Steam Workshop / шаринг обоев.
- Интерактивные обои с реакцией на мышь, аудио-визуализаторы (см. §11).
- Кроссплатформенность. Только Windows 10 1903+ / 11.
- Установщик и автообновления в v0.1.

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Рантайм | **.NET 10 (LTS)**, C# 14, `net10.0-windows` | Уже стоит SDK 10.0.302. Лучший на Windows interop, один процесс. |
| UI настроек | **WPF** | Зрелый, per-monitor DPI v2, нулевая боль с P/Invoke и `SetParent`. WinUI 3 хуже дружит с окнами-в-`WorkerW` и с треем. |
| Трей | `System.Windows.Forms.NotifyIcon` (`<UseWindowsForms>true</UseWindowsForms>`) | В коробке, 0 пакетов. Если меню выглядит слишком «Windows 7» — заменить на `H.NotifyIcon.Wpf`. |
| Win32/COM interop | руками, ~40 объявлений | План был перейти на **`Microsoft.Windows.CsWin32`** в v0.3, но и там сигнатуры оказались тривиальными: RECT, POINT, пара флагов. Генератор кода с его обёртками `HWND`/`PCWSTR`/`BOOL` добавил бы больше движущихся частей, чем убрал. Итог — ноль NuGet-пакетов во всём приложении. |
| Статические обои | **`IDesktopWallpaper`** (COM, в коробке Windows) | Умеет per-monitor из коробки: `SetWallpaper(monitorId, path)`, режимы вписывания, стабильные ID мониторов. Никаких хаков. |
| Видео | **libmpv** (`libmpv-2.dll`, P/Invoke ~120 строк) | Бесшовный `--loop-file=inf`, `--hwdec=auto-safe`, самый низкий CPU, встраивание в HWND через `--wid`. |
| Конфиг | `System.Text.Json` + один `config.json` | Никакой БД. |
| Логи | ~20 строк своего роллинг-логгера в `%LOCALAPPDATA%` | `Microsoft.Extensions.Logging` тут оверкилл. |
| Веб-обои | **WebView2** (`Microsoft.Web.WebView2`) | Рантайм предустановлен в Windows 11, пакет — тонкая обёртка. Живёт в тех же окнах слоя, что и видео: отдельного слоя не понадобилось. |
| Тесты | один `.cs` с `assert` на плейлист-движок, расписание и парсинг конфига | Единственная нетривиальная логика без ввода-вывода. |

**Чего в стеке нет и не будет:** DI-контейнера, MVVM-фреймворка, ORM, отдельного бэкенд-процесса, Electron.

**Пакетов ровно один** — обёртка WebView2, и появился он только в v0.4. Всё остальное, включая COM и полсотни объявлений Win32, написано руками.

**Альтернативы видео-бэкенда** (если libmpv не зайдёт):
- `LibVLCSharp` + `VideoLAN.LibVLC.Windows` — ставится одним NuGet, но цикл с микро-заиканием и выше CPU.
- Media Foundation / `MediaPlayerElement` — 0 зависимостей, но **нет HEVC/AV1 без платных расширений**. Для пользовательских файлов дисквалифицируется.

**Лицензии:** libmpv по умолчанию GPLv2+. Для личного проекта неважно; для закрытых исходников нужен LGPL-билд mpv/ffmpeg.

## 3. Архитектура

Один процесс, один mutex (single instance).

```
App (WPF, ShutdownMode = OnExplicitShutdown)
├── TrayIcon            NotifyIcon + контекстное меню
├── HotkeyHost          message-only HWND, RegisterHotKey, WM_HOTKEY
├── Config              config.json, атомарная запись, горячая перезагрузка с ретраями
├── MonitorSet          мониторы + стабильные ID, реакция на WM_DISPLAYCHANGE
├── PlaylistEngine      таймер, порядок/шаффл, next/prev, FileSystemWatcher
├── StaticLayer         IDesktopWallpaper — картинки            (v0.1)
├── VideoLayer          слой рабочего стола + окно на монитор + libmpv (v0.3)
└── PauseWatcher        полноэкранка / батарея / локскрин / RDP → Pause|Resume
```

Ключевое разделение: **картинки не требуют ни одного хака**, видео требует `WorkerW`. Поэтому это два независимых слоя, и v0.1 живёт вообще без `WorkerW`.

## 4. Механика Windows (самое хрупкое)

### 4.1 Статические обои — `IDesktopWallpaper`

```
CLSID_DesktopWallpaper  C2CF3110-460E-4fc1-B9D0-8A1C0C9CC4BD
IID_IDesktopWallpaper   B92B56A9-8B55-4E14-9A89-0199BBB6F93B
```

Нужные методы: `GetMonitorDevicePathCount` / `GetMonitorDevicePathAt` / `GetMonitorRECT` / `SetWallpaper(monitorId, path)` / `SetPosition` / `SetBackgroundColor`.

`DESKTOP_WALLPAPER_POSITION`: `Center=0, Tile=1, Stretch=2, Fit=3, Fill=4, Span=5`.

- `monitorId` — строка вида `\\?\DISPLAY#SAM0F94#5&...`, **стабильна между перезагрузками и переподключениями**. Это и есть ключ конфига, а не индекс монитора.
- `SetWallpaper(null, path)` — на все мониторы сразу.
- **Свой таймер слайд-шоу, а не `SetSlideshow`.** Встроенный слайд-шоу Windows применяет один список ко всем мониторам — нам нужен свой плейлист на монитор.
- **Потеря качества:** Windows перекодирует обои в JPEG в `%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper`. Лечится один раз: `HKCU\Control Panel\Desktop\JPEGImportQuality` = `100` (DWORD). Ставить при первом запуске.
- **`SetPosition` глобальный** — он не принимает `monitorId`. Вписывание одно на все мониторы; Windows применяет его к каждому монитору по его собственным размерам, но задать `Fill` на одном и `Fit` на другом нельзя. Разное вписывание = свой рендерер, то есть v0.3.
- **Плавных переходов тут нет**, и API для них не существует. Хочешь crossfade — картинки тоже придётся рисовать самому в `WorkerW` (риск R4).

### 4.2 Видео — окно в слое рабочего стола

Самое хрупкое место проекта. Разбиралось опытным путём: рабочая раскладка найдена
перебором 4 родителей × 6 техник привязки, а недостающий флаг вычитан прямо из окна
Wallpaper Engine. Три вещи, каждая из которых по отдельности ломает всё:

**1. `WorkerW` может быть не окном верхнего уровня.**
Классика (Win10, ранние Win11): после сообщения `0x052C` Explorer выносит `WorkerW`
наверх, соседом за окном с `SHELLDLL_DefView`. На Windows 11 26200 этого не происходит —
`WorkerW` лежит **внутри `Progman`**, и `EnumWindows` его не видит в принципе:

```
Progman                       5120×1440
├── SHELLDLL_DefView                      иконки, выше в z-порядке
│   └── SysListView32
└── WorkerW                   5120×1440   слой обоев, сюда и вешаемся
```

Искать надо оба варианта: сперва соседа верхнего уровня, потом `FindWindowEx(progman, …, "WorkerW")`.

**2. Классический поиск обязан проверять размер.**
В системе полтора десятка служебных окон класса `WorkerW` размером 136×39. Без проверки
находится первое попавшееся, и всё молча не работает.

**3. Окно обязано быть layered — это и есть главный секрет.**
DWM композитит дочерние окна внутри `WorkerW` только у layered-окон. Обычное окно там
создаётся, привязывается, числится видимым — и не рисуется. Именно этим наша реализация
отличалась от Wallpaper Engine, у которой `WPEVideoWallpaper` имеет
`exstyle = 0x08280000` — `WS_EX_LAYERED | WS_EX_NOACTIVATE`.

При этом layered-окно **нельзя создать сразу дочерним**: `CreateWindowEx` с
`WS_EX_LAYERED | WS_CHILD` возвращает ноль. Порядок обязан быть таким:

```
CreateWindowEx(WS_EX_LAYERED | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW, …, WS_POPUP)
SetParent(hwnd, workerW)
SetWindowLong(hwnd, GWL_STYLE, (style & ~WS_POPUP) | WS_CHILD | WS_VISIBLE)
SetLayeredWindowAttributes(hwnd, 0, 255, LWA_ALPHA)     // непрозрачное
SetWindowPos(hwnd, …)                                   // координаты внутри WorkerW
```

Дальше по мелочи:

- Координаты внутри `WorkerW` считаются от его собственного левого верхнего угла, а он
  растянут на весь виртуальный стол: на мониторе слева от основного начало отрицательное.
- **Explorer перезапускается — слой умирает.** Ловим `RegisterWindowMessage("TaskbarCreated")`
  на обычном (не message-only!) окне: широковещательные сообщения до message-only не доходят.
- `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` до создания любого окна.
- Своего фолбэк-фона не нужно: под видео остаются прежние обои, они и есть запасной вариант.

**Способ привязки подбирается на запуске, а не зашит.** Кандидаты пробуются по порядку,
проверка — чтение содержимого родителя через `PrintWindow`, а не цвета экрана: так замер
не врёт, даже когда рабочий стол закрыт окнами или поверх лежит прозрачный оверлей.
Первые два кандидата кладут видео под иконки, последние два — поверх, и включаются только
если нормального слоя на этой сборке нет.

**Диагностика.** `--workerw` печатает дерево окон, перебирает способы и говорит, какой
работает; `--workerw --visual` прогоняет их по очереди заливкой экрана — когда прибор
подводит и решают глаза; `--videosweep <файл>` перебирает способы вывода mpv.

### 4.3 libmpv

Минимальный набор P/Invoke: `mpv_create`, `mpv_set_option_string`, `mpv_initialize`, `mpv_command`, `mpv_set_property_string`, `mpv_terminate_destroy`.

Опции на старте:

```
wid                    = <hwnd дочернего окна>
loop-file              = inf
audio                  = no      (или volume=0, если нужен звук по хоткею)
hwdec                  = auto-safe
vo                     = gpu
gpu-api                = d3d11
keepaspect             = yes
panscan                = 1.0     (fill; 0.0 = fit)
input-default-bindings = no
osc                    = no
osd-level              = 0
```

Пауза: `mpv_set_property_string(ctx, "pause", "yes")` — декодер останавливается, GPU освобождается.

### 4.4 Правила паузы — `PauseWatcher`

| Условие | Как определить | Действие по умолчанию |
|---|---|---|
| Полноэкранное приложение / игра | `SHQueryUserNotificationState()` → `QUNS_RUNNING_D3D_FULL_SCREEN` или `QUNS_PRESENTATION_MODE`. **`QUNS_BUSY` брать нельзя**: он выставляется и на обычных развёрнутых окнах, по нему видео стоит почти всегда | пауза видео |
| Игра в безрамочном окне | `GetForegroundWindow` + сравнение rect с rect монитора. Обязательно пропускать сам рабочий стол и панель задач (`Progman`, `WorkerW`, `SHELLDLL_DefView`, `Shell_TrayWnd`) — иначе достаточно нажать Win+D, и видео встаёт навсегда | пауза этого монитора |
| Работа от батареи | `GetSystemPowerStatus` | пауза видео |
| Экран заблокирован / смена сессии | `SystemEvents.SessionSwitch` | пауза всего |
| RDP-сессия | `GetSystemMetrics(SM_REMOTESESSION)` | видео выключить совсем |

Опрос раз в 2 с и только пока есть активное видео. Все правила настраиваются.

## 5. Модель данных

`%APPDATA%\Wallpaper\config.json`:

```json
{
  "version": 1,
  "startWithWindows": true,
  "fit": "fill",
  "pauseRules": {
    "fullscreenApp": "pause",
    "onBattery": "pause",
    "lockScreen": "pause",
    "remoteSession": "stop"
  },
  "monitors": {
    "\\\\?\\DISPLAY#SAM0F94#5&1a2b3c&0&UID4353": {
      "label": "Основной 27",
      "mode": "playlist",
      "playlistId": "nature",
      "video": { "path": null, "volume": 0 }
    },
    "\\\\?\\DISPLAY#GSM5B09#5&1a2b3c&0&UID4354": {
      "label": "Вертикальный",
      "mode": "static",
      "path": "D:/wp/portrait/01.jpg"
    }
  },
  "playlists": [
    {
      "id": "nature",
      "name": "Природа",
      "folders": [{ "path": "D:/wp/nature", "recursive": true }],
      "files": [],
      "intervalSeconds": 900,
      "order": "shuffle",
      "advanceOnUnlock": false
    }
  ],
  "hotkeys": {
    "next": "Ctrl+Alt+Right",
    "prev": "Ctrl+Alt+Left",
    "togglePause": "Ctrl+Alt+P",
    "quickPicker": "Ctrl+Alt+W",
    "revealCurrent": "Ctrl+Alt+E",
    "playlist1": "Ctrl+Alt+1",
    "playlist2": "Ctrl+Alt+2"
  }
}
```

Правила:

- Ключ монитора — `monitorId` из `IDesktopWallpaper`. Монитор отключили → запись **сохраняется** и применится при возврате.
- `mode`: `off` | `static` | `playlist` | `video`.
- `fit` лежит в корне, а не внутри монитора: `SetPosition` глобальный (§4.1).
- Состояние проигрывания (текущий индекс, seed шаффла) — в отдельном `state.json`, чтобы не мешать пользователю править конфиг руками.
- Сохранение атомарное: запись во временный файл + `File.Move(overwrite: true)`.

## 6. Горячие клавиши

`RegisterHotKey` на message-only окне, `WM_HOTKEY` в цикле сообщений.

**К какому монитору применяется:** к тому, **под которым сейчас курсор** (`MonitorFromPoint(GetCursorPos())`). Добавить `Shift` к комбинации — применить ко всем мониторам. Одно правило, предсказуемое, без «активного монитора» в настройках.

| По умолчанию | Действие |
|---|---|
| `Ctrl+Alt+→` | Следующие обои |
| `Ctrl+Alt+←` | Предыдущие |
| `Ctrl+Alt+Shift+→` | Следующие на всех мониторах |
| `Ctrl+Alt+P` | Пауза / продолжить слайд-шоу |
| `Ctrl+Alt+1…9` | Переключить плейлист на мониторе под курсором |
| `Ctrl+Alt+W` | Быстрый выбор (оверлей с миниатюрами) |
| `Ctrl+Alt+E` | Открыть папку текущей картинки в проводнике |
| `Ctrl+Alt+M` | Звук видео вкл / выкл |

Если `RegisterHotKey` вернул `false` (комбинация занята) — не падать: показать это в настройках рядом с полем и в тултипе трея.

## 8. Окно настроек

Одно окно, три вкладки. Без визардов и онбординга.

1. **Мониторы** — кликабельная схема расположения мониторов (rect'ы из `GetMonitorRECT`), под ней настройки выбранного: режим, плейлист или файл, вписывание, цвет фона.
2. **Плейлисты** — список слева, содержимое справа сеткой миниатюр. Drag&drop папок и файлов прямо в сетку. Интервал, порядок, «включая подпапки».
3. **Общее** — автозапуск, правила паузы, горячие клавиши, папка кэша миниатюр, размер кэша.

**Миниатюры:** `IShellItemImageFactory::GetImage` — один API даёт превью и для картинок, и для видео (через shell thumbnail provider). **Своего кэша на диске нет:** Windows уже ведёт `thumbcache_*.db`, второй такой же поверх него — лишняя работа и лишний мусор в `%LOCALAPPDATA%`. В памяти держим до 600 миниатюр по 200 px (~50 МБ) и при переполнении чистим целиком.

## 9. Этапы

**v0.1 — ядро (без единого хака). Готово.** Трей и меню, конфиг, `IDesktopWallpaper`, per-monitor статика, плейлисты и слайд-шоу, горячие клавиши, автозапуск, `FileSystemWatcher` на папки, горячая перезагрузка `config.json`, single instance.
*Проверено на двух мониторах 2560×1440: независимые курсоры на общем плейлисте, смена по таймеру, правка конфига на лету. 33 проверки в `--selftest`.*

**v0.2 — интерфейс. Готово.** Окно настроек на три вкладки (схема мониторов, сетка миниатюр, общие настройки), drag&drop папок и файлов, оверлей быстрого выбора по `Ctrl+Alt+W`, редактор горячих клавиш с захватом комбинации, тема под системную вместе с тёмным заголовком окна.
*Проверено вживую: все три вкладки, горячая перезагрузка конфига в открытом окне, оверлей на нужном мониторе, захват комбинации с перерегистрацией.*

**v0.3 — видео. Готово.** Слой рабочего стола с автоподбором способа привязки, окна на монитор, libmpv, `PauseWatcher`, реакция на перезапуск Explorer и смену разрешения, настройки видео и правил паузы в окне, диагностика `--workerw` и `--videosweep`.
*Проверено на двух мониторах 2560×1440: два ролика 4K60 h264 одновременно, видео под иконками, 22 % одного ядра из двенадцати и 580 МБ. Пауза срабатывает на полноэкранном окне и только на закрытом мониторе.*

**v0.5 — готово.** Видео и веб-страницы внутри плейлистов, выключатель обоев целиком, отключаемые по отдельности горячие клавиши, подсказки в настройках, возврат исходных обоев при выходе, `--quit`. Плюс починка взаимной блокировки с Explorer (§10a) и невидимый пробник слоя.

**v0.4 — готово.** Веб-обои на WebView2 (локальный html и адреса, canvas и WebGL), анимированные GIF/APNG через тот же mpv, звук по горячей клавише, расписание смены плейлиста по времени суток с редактором в окне.
*Проверено: на одном мониторе 4K60 видео, на другом анимированная страница на canvas — одновременно, 6,5 % одного ядра из двенадцати и 275 МБ.*

**Установщик решили не делать.** Для приложения, которое живёт в одной папке и прописывается в автозапуск одной галкой, Velopack — это отдельный конвейер сборки ради задачи, которой нет. Достаточно `dotnet publish -c Release -o publish`.

## 10a. Взаимная блокировка с Explorer

Самый дорогой урок проекта, найденный уже после v0.4.

**Симптом.** Приложение замирает, а вместе с ним виснет рабочий стол всей системы:
посторонний процесс, вызвавший `IDesktopWallpaper`, тоже встаёт намертво. Убийство
нашего процесса всё чинит.

**Причина.** `SetParent` окна в чужой `WorkerW` связывает потоки: наш и Explorer'а.
После этого любой блокирующий вызов COM оболочки из UI-потока замыкает круг — Explorer
шлёт сообщение нашему окну и ждёт, наш поток ждёт возврата из COM. COM оболочки
однопоточный, поэтому следом встают и все остальные процессы.

**Правило.** UI-поток, владеющий окнами внутри Explorer, **никогда** не ждёт COM оболочки.
Весь такой COM — и `IDesktopWallpaper`, и `IShellItemImageFactory` для миниатюр — живёт
на отдельных STA-потоках (`ComThread`), работа туда только отправляется. Следствия:

- `Desktop.Monitors()` отдаёт снимок, а не ходит в COM; снимок обновляют по `WM_DISPLAYCHANGE` и раз в минуту.
- `SetWallpaper` не возвращает результат: существование файла проверяется до отправки.
- Ждать очередь (`Flush`) можно только при выходе — после того, как окна из слоя уже сняты.

**Как проверить, что вернулось.** Запустить приложение и из другого процесса позвать
`Wallpaper.exe --monitors`. Отработал — блокировки нет; завис — она снова здесь.

## 10b. Смена обоев убивает слой

Второй урок того же семейства, найденный по жалобе «видео справа заменилось картинкой,
и приложение зависло».

**Симптом.** Монитор A крутит слайд-шоу, монитору B назначено видео. Через один интервал
видео на B пропадает, показывая обои под собой. Дальше всё разваливается.

**Причина.** `IDesktopWallpaper.SetWallpaper` заставляет Explorer перестроить рабочий стол,
и при этом он уничтожает чужих детей своего `WorkerW` — то есть наши окна. В журнале это
видно буквально: «окно слоя убито Explorer'ом», ровно раз в интервал слайд-шоу.

**Полумера.** Проверять окна по таймеру и пересобирать слой (`VideoLayer.Verify`). Работает,
но даёт мигание при каждой смене картинки. Оставлено как страховка от внешних причин —
перезапуска Explorer, смены разрешения.

**Решение.** Пока слой занят (`LayerBusy` — хоть одному монитору назначено видео или
страница), картинки слайд-шоу тоже рисуются в слое через mpv, а `IDesktopWallpaper` вообще
не вызывается. Убивать становится нечего. Движок плейлистов при этом не знает, чем рисуют:
он лишь просит `Present(монитор, файл)`, а способ выбирает владелец слоя.

Заодно это открывает дорогу к плавным переходам между картинками (риск R4): когда картинки
рисует наш слой, crossfade перестаёт упираться в отсутствующий API Windows.

## 10c. Чьи это обои

Приложение обязано вернуть при выходе то, что стояло до него. Наивное «запомнить один раз
при первом запуске» ломается сразу: пользователь ставит свою фотографию, пока приложение
выключено, — и она не попадает в запомненное, а возвращается что-то давнее.

Просто «запоминать при каждом запуске» ломается иначе: после сбоя на экране остаются наши
же обои, и они становятся «оригиналом» навсегда.

**Правило.** В состоянии хранится `LastApplied` — что мы сами последний раз поставили на
каждый монитор. На запуске сравниваем с тем, что на мониторе сейчас:

- совпало — обои остались от нас, запомненный оригинал не трогаем;
- не совпало — их сменил пользователь, запоминаем именно это.

Восстановление тоже обновляет `LastApplied`: после возврата оригинала на мониторе стоит
то, что мы поставили, и следующий запуск это узнает.

## 10d. Исключение в оконном колбэке убивает процесс молча

Приложение исчезало целиком при выборе картинки в быстром выборе, **не оставляя ни строчки
в журнале** — не срабатывали ни `AppDomain.UnhandledException`, ни
`Application.DispatcherUnhandledException`. В журнале Windows при этом код `0xc000041d`.

Причина: исключение, выпущенное из системного колбэка (оконная процедура, ловушка
`HwndSource.AddHook`), .NET протащить обратно через нативный кадр не может. Среда объявляет
процесс безнадёжным и убивает его на месте, минуя все обработчики.

Сам источник исключения был безобидный: клик по плитке отнимал фокус, `Deactivated`
закрывал оверлей, а следом `Apply` закрывал его второй раз — WPF на закрытом окне бросает
`InvalidOperationException` прямо внутри обработки сообщения.

**Правило.** Закрытие окна идёт через флаг «уже закрываемся». Любой обработчик, который
вызывается из нативного колбэка, обёрнут в глухой `try/catch` с записью в журнал: там
исключение обязано умереть на месте, потому что дальше его ловить уже некому.

## 10e. Нулевой контекст libmpv убивает процесс

Второй способ исчезнуть без следа в журнале, из той же семьи, что и 10d. На мониторе
крутился плейлист, в котором рядом с картинками лежала веб-страница. Поверхность слоя
под страницей — это WebView2, контекста mpv у неё нет. Когда плейлист переходил со
страницы на картинку, код переиспользовал ту же поверхность и звал `mpv_command`
с нулевым контекстом. libmpv на это не отвечает ошибкой — она падает в access violation
(`0xc0000005` внутри `coreclr.dll`), и процесс умирает мгновенно.

Стек нашёлся только в журнале Windows, в записи провайдера **.NET Runtime**: своих
записей приложение сделать уже не успевает.

**Правило.** Поверхность переиспользуется, только если совпал её род: mpv умеет подменять
файл на лету, WebView2 — нет. Разошлись — окно пересоздаётся. Плюс `Mpv.Command`
проверяет контекст: в нативную библиотеку с нулём не ходим никогда.

## 10f. Вернув чужие обои, свои надо ставить заново

Прямое следствие 10c. При выходе приложение возвращает на мониторы обои пользователя —
значит при следующем запуске наших там уже нет. А стартовая синхронизация трогала монитор
только если курсор плейлиста «протух» или подошёл срок смены: в остальных случаях она
полагалась на то, что Windows восстановила картинку сама.

Результат: после перезапуска монитор показывал обои пользователя до ближайшей смены по
таймеру, а на мониторе с паузой — вообще навсегда.

**Правило.** Первый проход синхронизации после запуска всегда показывает то, что записано
в курсоре, даже если срок ещё не подошёл. Курсор и таймер при этом не двигаются: картинка
досиживает свой интервал. Последующие проходы (их вызывает любое изменение конфига)
монитор не трогают — иначе каждая правка настроек давала бы мигание.

## 10g. IDesktopWallpaper не берёт файлы из папки приложения

Режим «Размытие» собирает картинку под размер монитора и отдаёт её в обои вместо исходной.
Собранное складывалось в `%APPDATA%\Wallpaper\backdrop`, и `IDesktopWallpaper::SetWallpaper`
на каждый такой файл отвечал `0x80070002` — «не удаётся найти указанный файл». Файл при этом
лежал на месте: `File.Exists` его видел, `System.Drawing` открывал, размер 2560×1440,
а классический `SystemParametersInfo` тот же самый файл принимал без возражений.

Перебором выяснилось, что дело не в файле и не в формате — jpeg и png отказывались
одинаково, — а в расположении. Скопированный в другую папку файл ставился сразу. Перенос
кэша в `%LOCALAPPDATA%\Temp\Wallpaper\backdrop` снял отказ полностью. Почему оболочка
не принимает пути внутри папок приложения в AppData — выяснить не удалось.

**Правило.** Всё производное — то, что можно собрать заново, — складываем во временную
папку (`Paths.Cache`), а не рядом с конфигом. Заодно это правильнее и само по себе: кэш
не должен ни синхронизироваться между машинами, ни расти в профиле.

## 11. Что специально отложено

- **Аудио-реактивные обои** — WASAPI loopback (`NAudio.WasapiLoopbackCapture`) + FFT + мост в страницу через `postMessage`. Теперь, когда веб-слой есть, это стало дешевле, но всё ещё никем не запрошено.
- **Обои с реакцией на курсор** — требует хука ввода, конфликтует с `WS_EX_NOACTIVATE`.
- **Синхронизация конфигов между машинами** — положить `config.json` в облачную папку и сделать симлинк.

## 12. Целевые показатели

- Простой (статика): CPU ~0 %, RAM < 120 МБ.
